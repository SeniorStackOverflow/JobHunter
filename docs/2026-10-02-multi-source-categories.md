# Категории по источникам (2026-10-02)

Оператор отметил, что настройки и логика заточены под один источник: категории
задавались тремя общими текстовыми полями, а пользователь не знает, какие категории
есть у адаптера и как они точно называются.

## Что было

- `job_preferences.allowed_categories`, `auto_send_categories`, `forbidden_categories` —
  три списка на весь профиль, свободный текст через запятую. Значения должны были
  совпадать со slug-ами адаптера (`others`, `warehouses`, `operating`).
- Те же списки читали фильтр вакансий, запрос к модели, политика автоотправки и
  дневная цель — без учёта источника вакансии.
- Область обхода (`incremental_scan.category_slugs`) задавалась отдельно, в JSON
  конфигурации источника, и с выбором в панели связана не была.

У каждого адаптера свой набор категорий, поэтому одним общим списком несколько
источников описать нельзя.

## Что изменено

### Модель

`profile_source_preferences` (профиль × источник, там уже хранился флаг «источник
включён») получила четыре колонки: `categories_configured`, `search_categories`,
`auto_send_categories`, `excluded_categories`. Значения — идентификаторы категорий
самого источника (`source_categories.external_id`), которые обходчик собирает с сайта.
У Rabota.md их 53, с русскими названиями.

Миграция `d8e2f4a6b1c3` копирует нынешние общие списки в строку каждого источника
профиля без изменений. Поведение после миграции прежнее.

Общие списки профиля остаются значением по умолчанию для источника, у которого своего
выбора ещё нет. Они входят в отпечаток настроек оценки и при сохранении категорий
источника не переписываются.

### Логика

`app/profiles/source_categories.py` — единая точка: `category_policy(profile, source)`.
Её используют:

- фильтр вакансий (`DeterministicPrefilter`): разрешена ли категория, исключена ли;
- запрос к модели: в контекст попадают категории источника вакансии;
- политика (`category_allowed_for_auto_send`) и дневная цель: список автоотправки
  источника;
- обход: инкрементальный скан источника охватывает категории, выбранные для поиска
  обрабатываемыми профилями. Пока никто ничего не выбрал, действует список из
  конфигурации источника. Адаптер сужает обход методом `set_incremental_categories`;
  адаптеры без категорий не затрагиваются.

Правила выбора: «автоотправка» подразумевает «искать»; «исключить» сильнее обоих;
идентификатор, которого нет в каталоге источника, отклоняется.

### Переоценка только затронутых вакансий

Раньше любое изменение категорий меняло отпечаток настроек, и все вакансии профиля
уходили на переоценку: в PROD это 1756 активных вакансий трёх выбранных категорий;
29 сентября такое изменение дало 1868 обращений к модели за день при обычных 60–80.

Теперь при сохранении сравнивается вердикт по категориям для каждой вакансии
источника до и после, и отпечаток сбрасывается только у оценок вакансий, для которых
вердикт изменился. Изменение одной лишь автоотправки ничего не переоценивает: это
правило доставки, политика перепроверяет его сама.

### Панель

В «Критериях и лимитах» три текстовых поля убраны. В разделе «Источники» у каждого
источника — список всех его категорий по названиям; у каждой категории одно из четырёх
состояний: «Не искать», «Искать», «Автоотправка», «Исключить». Есть поиск по названию
и счётчики. Выбранные категории показаны первыми. Работает в панели администратора и
в кабинете пользователя; сохранять можно только для своего профиля.

Источник без категорий показывает пояснение, что отбор идёт без фильтра по категориям.

### Внешние интерфейсы

Общие списки больше нельзя менять через `PUT /api/v1/preferences` и MCP
`update_job_preferences` (ошибка валидации). В MCP добавлены `get_source_categories`
(источники, их известные категории и текущий выбор) и `set_source_categories`.
`get_job_preferences` по-прежнему отдаёт общие списки — значения по умолчанию.

## Выкладка и откат

Нужны миграция `d8e2f4a6b1c3`, сборка образа и перезапуск семи сервисов. Миграция
только добавляет колонки и копирует списки; оценки не затрагивает.

После выкладки обход, отбор и автоотправка работают как раньше, пока в панели не
изменён выбор. Добавление категории расширяет обход источника и число обращений к
модели — на вакансии этой категории, которых не было в уже выбранных.

Откат: прежний код читает общие списки профиля, которые миграция не меняет, и не
знает о новых колонках; `alembic downgrade c5d7a9e1f3b2` удаляет колонки. Выбор,
сделанный в панели после выкладки, при откате теряется.

## Что остаётся привязанным к одному источнику

Не менялось в этой работе:

- псевдонимы категорий в фильтре (`_SOURCE_CATEGORY_ALIASES`) — общие для всех
  источников;
- категория резюме — свободный текст, сравнивается с категорией вакансии по
  совпадению строки;
- города: нормализация рассчитана на Кишинёв и Бельцы;
- служебные задачи планировщика и настройки прокси относятся только к Rabota.md.
